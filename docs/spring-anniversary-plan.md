# 第九张史莱姆牌 · 新春×一周年特别版方案

> v3（2026-11-18，全部决策已拍板，方案冻结）。上线目标 **2027-02-01**。

## 0. 已拍板决策

- 一个版本承载新春 + 一周年双主题，按 2027-02-01 排期（除夕 2027-02-05）。
- 新增 **2 个卡牌系列**：新春、一周年。
- 新增玩法模式：**无限年**。
- **不做卡池限定机制**：新系列卡即常驻卡，进正常混池，无活动期出现率、无绝版。
- 新春装饰 UI 变换。
- 新增敌人。
- 附带两项调整：角色动画（位置/角度，无新素材）；流程重构减负。

## 1. 新增系列（CardSeries 扩容）

`CardSeries` 是 enum（1–8），加 `Spring = 9`（新春）、`Anniversary = 10`（一周年）。改动点收敛在：

| 位置 | 改动 |
|---|---|
| `CardDef.cs` | enum 加 2 项；`Series.All`、`DisplayName`、`IdOf`、`FromName`、`Blurb`、`IsBasic` 各加 2 分支 |
| `Theme.cs` | 2 个系列色（新春：红金；一周年：金紫） |
| `SpriteForge.cs` | 系列色板映射 |
| `cards.csv` | 追加 20 行（145–164），图鉴按 All 遍历自动收录 |
| Glossary / 平衡回归 | 新卡效果若用新机制需补词条；coretest `all` 全量跑 |

**卡表草案（冻结前需过平衡）**：

- **新春 ×12**：爆竹、烟花、春联双福、饺子护盾、年兽之息、红包雨、灯笼高照、舞狮踏鼓、守岁灯、屠苏酒、开门炮、瑞雪兆丰年。基调：红金、热闹、爆发与庆祝（部分复用灼烧/连锁结算，不发明新状态则零 Glossary 成本）。
- **一周年 ×8**：第九张史莱姆牌（纪念梗卡，与"9"挂钩）、时光胶囊、九连胜、周年庆典、初见之约、九世同堂、致每一位玩家、下一年的约定。基调：低数量、高稀有、带纪念性文案（趣闻列这次要填）。

总卡量 144 → 164。混池稀释用现有稀有度权重吸收，平衡回归验证抽感。

## 2. 无限年模式

无尽爬层，难点在 RunDirector 的 Chapter 封顶假设要打开：

- **入口**：HomeScreen 新按钮「无限年」。
- **规则**：无节点图，直线推进——1 层 1 战，每 5 层 1 精英、每 10 层 1 Boss（Boss 轮换取自全部章节 Boss，难度按虚拟章节数缩放）；每层战后奖励（选卡/回血/金币三选一）。
- **难度**：复用 `ScaleHp`/`ScaleDamage` 的 chapter+floor 参数，虚拟章节数随层数无上限递增。
- **卡组（定案）**：固定「新春构筑」起手——10 张固定卡组，含 2 张新春系列核心卡；模式内抽卡加权新春系列。新系列有主场，平衡可控，与存档解耦。
- **记录**：最高层数 + 单次最长连击存档（SaveData v4 → v5）。
- **成就**：TapSDK 后台新增 2 个 flag 型（抵达 10 层 / 抵达 30 层），客户端注册同步。
- **死亡**：清 RunDeck/RunNodeId/RunMapSeed 等同现有规则，最高层数单独持久化不随局清。

## 3. 新增敌人（31 → 约 37）

全部走 `EnemyRoster.BuildAll()` 工厂方法 + SpriteForge 回退立绘（真美术后补）：

- **新春 5**：鞭炮鬼（普通，自爆）、灯笼精（普通，灼烧）、年画妖（精英，镜像）、瑞雪兽（精英，冰冻）、**年兽（Boss）**——回合性变招，喜庆压轴。
- **一周年 1**：**史莱姆九世（Boss，定案：仅无限年 30 层压轴）**——9 段血条按"9"设计，纪念向；普通局结构与遭遇逻辑不动。
- 普通/精英按章节进 `NormalPool`/`ElitePool`；无限年 Boss 轮换表把两只新 Boss 编入。

## 4. 新春装饰 UI

- **Theme 节日层**：Festival 调色覆盖主色（红金），Settings 留开关；判定窗口 **01-20 ~ 02-28**（小年前 ~ 元宵尾），DevPanel 加 `festival on/off` 强制开关供截图与回归。
- **HomeScreen**：灯笼（SpriteForge 程序化）、春联横幅、标题旁福字；进 Home 时一段短入场演出（灯笼落下/横幅展开，Tween 实现）。
- **图鉴/商店/战斗**：只换主题色 + 背景点缀，不动布局。
- BGM 复用现有 4 首，不做新音频。

## 5. 角色动画（无新素材）

挂在现有 `playerPortrait`（已记录 `playerBaseScale`）与敌人立绘 Image 上，全部 Tween 位移/缩放/旋转/染色：

| 场景 | 表现 |
|---|---|
| 待机 | 呼吸：y 缓浮 ±6px + scale 微脉动，相位随机避免双方同步 |
| 受击 | 后仰 10px + 闪白/闪红 100ms 回弹 |
| 攻击 | 突进至目标 30% 处 → punch 回位（0.25s） |
| 施法 | 上浮 15px + 光环 halo 亮度脉冲 |
| 死亡 | 缩小 + 淡出 + 影子收拢 |
| 卡牌打出 | 对应角色做一次轻量动作，避免"全场静止只有数字在跳" |

注意事项：动画期间输入锁不新增状态机，复用现有结算节奏；`Ui.ClearChildren` 重建容器时 Tween 要跟随目标销毁，防悬挂引用。

## 6. 流程重构 · 减负（已勾选冻结：a + b + d + e + f）

- a. **奖励屏并入节点屏**——战后 Reward 不再独立切屏（减 1 次跳转/局均 12+ 次）
- b. **战斗结算提速**——结算面板一键跳过、经验/金币数字合并滚动
- c. ~~Map→节点直连~~——未勾选，跳过
- d. **单局时长压缩**——周目 48 层砍短或缩短战斗平均回合；动平衡，放在 12 月下 – 1 月上缓冲位，若挤占 1 月中打包节点则降级为"缩短战斗平均回合"单项
- e. **登录链路减负**——Boot→Login→Home 三屏合并过渡动画（TapSDK 登录中态直接渲染在 Boot 上）
- f. **认知减负（贯穿原则，非独立工作项）**——单一屏幕信息不要太多太杂：Home/Map/Battle 三个重屏做信息降噪与层级梳理（次要数字收进详情、常驻控件分组、颜色只用于强调）。其他所有改动（含新春装饰）遵守同一原则：装饰不与信息抢层级。
